# Change: add-traceable-vector-retrieval

## Why

第 3 课已实现登录、按班级隔离与教研材料入库（`add-auth-rbac-class-knowledge`，已归档）。但材料入库后只能按标题浏览，教师与学生无法用一句自然语言在本班材料中定位相关内容；即使找到片段，也无法说明它出自哪份材料的哪一段。本变更在同一套系统上增加**限定班级范围、可溯源的知识库检索**：命中结果标注出处，无依据时明确返回未找到，不得编造出处。

## What Changes

- **正文切分与索引入库**：上传成功后，正文按策略切分为切片写入切片表；切片文本存关系库，向量存向量库，向量主键与切片主键一致。切分策略支持自动窗口（默认约 800 字、重叠约 10%）、自定义分隔符、Markdown 标题分章三种；教师可按新策略重建索引。
- **三种检索模式**：`keyword`（仅全文索引，不调用嵌入服务）、`vector`（问句嵌入后按班级过滤做余弦检索，低于阈值丢弃）、`hybrid`（两路独立过滤后按名次 RRF 融合，k = 60）。默认 `hybrid`。
- **内容溯源**：每条命中 MUST 给出材料标题、切片序号、字符区间与摘录，并支持打开对应材料；摘录取自关系库切片正文，不取自向量库。
- **检索侧班级隔离**：班级标识仅取自登录会话，请求中自带的班级编号一律丢弃；关键字与向量两条路径均须过滤，回表时再次核对；跨班检索对外表现为无命中（200 + 空列表），不得以 403/404 泄露资料归属。
- **问答接口与引用标注**：`POST /api/ask` 先做本班混合检索取前 4 条；有命中才调用生成模型撰写简短回答，回答中以 [1]、[2] 指回出处且与出处列表顺序一致；无命中直接返回固定文案「资料中未找到相关内容」，citations 为空，不调用生成模型。
- **故障降级**：向量库或嵌入服务不可用时，关键字检索仍可返回结果，向量与混合模式返回 503，不编造相似度分数；空查询返回 400。
- **最小暴露面**：向量库服务在 Compose 中不向宿主机映射端口；嵌入/对话网关密钥仅存服务端环境变量，浏览器只访问本站 `/api`。

## Capabilities

### New Capabilities

- `knowledge-retrieval`：切分与索引入库、关键字/向量/混合三种检索、命中溯源、检索侧班级隔离、问答接口与引用标注、故障降级、索引重建、组件暴露面约束等可验收行为。

### Modified Capabilities

（无——`auth-upload` 的登录、隔离、上传入库行为不变；切分与嵌入在上传事务提交之后追加，由 `knowledge-retrieval` 规约覆盖。）

## Impact

- 数据层：新增切片表（`knowledge_chunks` 或等价）；既有 `knowledge_entries.body_text` 保持上传原文不改写。
- 服务层：新增检索模块（切分、嵌入调用、检索、回答编排）；新增 `GET /api/search`（或等价）与 `POST /api/ask` 接口；材料列表页增加检索与问答入口。
- 部署层：Compose 新增向量库服务（Qdrant，无宿主机端口映射）；`.env.example` 增加嵌入/对话网关与向量库连接配置。
- 外部依赖：嵌入与对话两个网关（OpenAI 兼容接口），仅服务端调用，密钥不下发浏览器。
- 可运行实现按 `tasks.md` 在 Apply 阶段完成；本 change 当前以规约四件套为交付物。

## Non-goals（非目标）

本课/本 change **明确不做**以下内容：

- **流式输出与长对话**：不做流式响应、多轮对话管理与长上下文编排（第 5 课内容）；问答仅基于用户最新一句检索。
- **重排序**：不引入交叉编码器重排序。
- **编排框架**：不引入 LangChain、LlamaIndex 或 Dify 一类框架；切分、嵌入与检索由应用服务自行实现，便于对照规约逐条验收。
- **按班拆分向量集合**：以 `class_id` 过滤实现隔离，不为每个班级建独立 collection。
- **正文入向量库**：向量库 payload 仅存标识，不保存切片正文。
- **新文件格式**：上传解析范围沿用第 3 课（txt/md），不新增 PDF 等格式。
- **前端替代服务端安全**：不以隐藏入口作为班级隔离手段；向量分量不出现在页面或 API 响应中。
