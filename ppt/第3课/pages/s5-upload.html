5 上传入库

教师上传后写入磁盘、解析正文，并在同一事务中写入材料表与知识库表。

每步按同一顺序展开：知识点 → 其他可行方案与选择依据 → 本步要核对 → 动手要做。“怎么查”一列给出三处证据：规约读哪条、代码搜什么、运行做什么；发现不一致，先补规约或改实现。全课汇总见 实现方案核对总表。

本页步骤

1权限：谁可以上传2校验与写入磁盘3入库事务与下载鉴权

1权限：谁可以上传

上传是教师专属功能；仅隐藏按钮无效，必须以会话角色在服务端拒绝。

知识点

BFLA 垂直越权

Broken Function Level Authorization：学生调用只有教师可用的上传接口。仅隐藏前端按钮不能阻止越权。必须以会话角色在服务端拒绝，数据库与磁盘状态均不变。

本步要核对

核对项 本迭代应采用 怎么查（规约 / 代码 / 运行） 自检
学生调用上传接口的结果是什么？ 403，且材料表、知识库表行数与上传目录均不变。 规约：学生上传失败 Scenario
代码：搜上传 handler 的角色判断位置
运行：用学生 Cookie 调一次上传接口

动手要做

  • 仅教师可 POST /api/materials，成功建议 201。
  • 学生上传必须 403；两表行数不变，上传目录不新增文件。
  • 客户端声明自己是教师无效，仍以会话角色为准。

2校验与写入磁盘

白名单扩展名、服务端生成存储名、超限在读完整请求体之前拒绝。

知识点

白名单与路径穿越

只允许 .txt / .md。黑名单机制无法穷举所有危险类型，必须采用白名单。客户端文件名可含 ../，存储名必须服务端生成。上传目录不做静态暴露，读文件先鉴权。

其他可行方案与选择依据

方案 要点 本课如何取舍
先写入磁盘再等人审再入库 内容安全更严。 超出范围。本课校验扩展名、大小、UTF-8 后直接入库。

本步要核对

核对项 本迭代应采用 怎么查（规约 / 代码 / 运行） 自检
扩展名校验是白名单还是黑名单？ 白名单 .txt / .md；黑名单无法穷举。 规约：是否写明白名单
代码：搜扩展名允许列表
运行：分别上传 .exe、.md.exe 各一次
存储名由谁生成？ 服务端生成；客户端文件名只作展示标题，不参与路径构造。 规约：是否有路径穿越防护要求
代码：搜文件路径拼接位置
运行：上传文件名含 ../ 的文件，看文件实际写入路径

动手要做

  • 白名单 .txt / .md；其他扩展名 400，不留文件。
  • 大小上限走环境变量（如 MAX_UPLOAD_BYTES）；超限返回 413，应在读取完整请求体之前拒绝。
  • 内容必须是非空 UTF-8 文本，否则 400。
  • 存储名由服务端生成；客户端文件名只作展示标题，不得参与构造路径。

3入库事务与下载鉴权

材料行与知识库行同事务，失败不留孤儿；下载走鉴权接口，不暴露静态路径。

知识点

上传是事务

材料行与知识库行必须处于同一事务。只写入磁盘而不入库，第 4 课检索将没有数据；只入库而不写入磁盘，下载将无法完成。失败时要回滚并删除已写入的文件，不得残留孤儿文件或孤儿记录（orphan）。

知识库在本课的目的

预置可查询正文，不是做问答。解析失败与非法扩展名都应 4xx，且两表与目录无残留。清理策略写进规约才能验收。

其他可行方案与选择依据

方案 要点 本课如何取舍
对象存储服务（AWS S3 / 阿里云 OSS） 文件存储与 api 本地磁盘解耦，利于多副本部署。 本课单实例本地目录即可。多副本再迁移到对象存储。
消息队列异步入库 上传接口可立即返回，解析失败可重试。 代价过高。本课采用同步写入磁盘并在同一事务中入库，失败路径更易验证。
材料与正文合成一张表 减少一次事务。 可。本课拆两表是为第 4 课检索预留 knowledge_entries；必须处于同一事务。

本步要核对

核对项 本迭代应采用 怎么查（规约 / 代码 / 运行） 自检
两张表是否处于同一事务？ 同事务，任一步失败整体回滚。 规约：是否写明事务要求
代码：看事务开启与提交的范围
运行：人为制造一次写入失败，检查是否半提交
失败是否留下孤儿文件或孤儿记录？ 无残留：回滚数据库行并删除已写入的文件。 规约：是否写明清理要求
代码：看回滚与文件删除逻辑
运行：触发一次失败后检查两表与上传目录
下载是否走鉴权接口？ 走 /api/materials/{id}/file，先校验会话与班级，跨班 404。 规约：是否写明下载鉴权要求
代码：搜静态目录暴露与文件 handler
运行：直接猜测 /uploads/<文件名> 请求一次

动手要做

  • 成功：写入磁盘 → 解析 → 在同一事务中写入 materials 与 knowledge_entries，班级取自会话。
  • 失败：4xx / 5xx，无孤立行、无未关联文件。
  • 本班教师与学生刷新列表必须看到新增条目（数据来自查询数据库）；其他班级的列表不得出现，按 ID 访问返回 404。
  • 详情返回标题、班级、时间与知识库正文，不要返回磁盘绝对路径。
  • 下载走 GET /api/materials/{id}/file，先校验会话与班级。直接猜测 /uploads/... 路径不得获取文件。

把否决理由用自己的话写进 design / 迭代说明；原文照录本表不算 ADR。

向 Harness 核对的参考提问

可直接复制到会话中使用。要求它逐项给出证据（文件与行号、命令与输出），找不到就明说、不许推测；回答只作线索，勾选前仍须亲自运行 verify 复核。

  1. 列出上传接口的完整校验链：扩展名是白名单还是黑名单？大小与内容如何校验？贴出各校验的文件与行号。
  2. 存储文件名由谁生成？仓库中是否存在把客户端文件名直接拼进存储路径的代码？
  3. materials 与 knowledge_entries 两表写入是否处于同一事务？贴出事务边界代码；演示一次第二步写库失败，确认文件与数据库均无残留。
  4. 用学生账号调用上传接口，贴出响应，并核对材料表、知识库表行数与上传目录是否均无变化。

想一想：判断与取舍

先对照本人规约作答。引用不到原文，先改规约再写代码。

  • 一次成功上传，哪些表各增一行？租户字段随会话还是随表单？后者带来什么风险？
  • 上传 .exe 或解析失败时，材料表、知识库表、uploads 目录的期望状态？是否写成可判定的 Scenario？
  • 学生调上传接口应返回什么状态码？该约束写在 Requirement / Scenario，还是只写在 design 的意向性描述里？
