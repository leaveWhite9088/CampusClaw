1凭据怎么存：哈希与环境变量

口令只以加盐慢哈希入库，所有密钥来自环境变量；缺失就启动失败，不留内置默认值。

知识点

口令与会话密钥

明文口令一旦入库即失去意义。用加盐慢哈希（bcrypt，一种专门用于口令的慢哈希算法）增加离线破解成本。SESSION_SECRET 用于保护会话标识，缺失必须启动失败，禁止内置默认值。密钥进 Git 是发布阻断项，泄漏后要轮换而不是只删提交。

其他可行方案与选择依据

方案 要点 本课如何取舍
argon2 替代 bcrypt 同为加盐慢哈希，argon2 更抗 GPU 并行破解。 可。本课用 bcrypt，Go 官方扩展库即可实现；不要存明文或可逆加密。
密钥写进源码默认值 本地环境始终可用。 否决。缺失必须启动失败。

核对项 本迭代应采用 怎么查（规约 / 代码 / 运行） 自检
口令是以哈希形式保存的吗？ bcrypt 加盐慢哈希；不存明文，也不用可逆加密。 规约：specs/auth-upload/spec.md R7（密码哈希与会话密钥）

动手要做

  • 口令用 bcrypt 哈希保存，不存明文。
  • 登录状态用 HttpOnly、SameSite=Lax Cookie 维护。
  • 口令、数据库凭据、会话密钥走环境变量；缺失则启动失败，不要内置默认值。

2失败响应同形：不给账号枚举留依据

未登录、越权、口令错误对外必须给出无法区分的响应，排障信息只进服务端日志。

知识点

默认拒绝与完整校验

未登录默认 401；未知角色不能升权。每次请求都要从会话再读角色与班级，不能信任上一次缓存在浏览器里的声明。

信息隐藏

错误提示、限流响应、跨班响应都可能成为账号枚举的依据。对外统一失败响应，排障信息只记录在服务端日志。

其他可行方案与选择依据

方案 要点 本课如何取舍
限流返回 429 对合法用户更可解释。 否决作为默认。429 会暴露账号正处于锁定状态，便于账号枚举。本课要求与口令错误返回相同响应。

本步要核对

核对项 本迭代应采用 怎么查（规约 / 代码 / 运行） 自检
三类失败响应是否同形？ 账号不存在、口令错误、被限流三类返回一致，不成为账号枚举的依据。 规约：是否写明统一失败响应
代码：搜错误返回分支，看是否有差异化文案
运行：三种输入各试一次，对比状态码、响应体与耗时

动手要做

  • 角色权限和班级边界均由服务端校验。
  • 上传校验扩展名、大小和内容；存储名由服务端生成。

建议一并写进 README 的行为

  • 跨班详情与文件返回 404，响应与不存在的记录一致。
  • /health 只表示进程存活，不要把数据库探活混进去。
  • 登录失败限流后的提示仍与口令错误一致，避免枚举账号。
  • 数据库不可用时业务接口返回 503，不要把已登录用户报成会话失效。

3部署侧默认拒绝：探针与网络

存活探针不查库、数据库不出内部网络，故障才不会互相放大。

知识点

存活与就绪

/health 表示进程还能响应。数据库探活属于就绪。混在同一个端点中，数据库抖动会被编排系统误判为容器故障并触发重启，放大故障。数据库不可用时业务接口应返回 503，不要把已登录用户判为 401。

其他可行方案与选择依据

方案 要点 本课如何取舍
在 /health 中一并检查数据库 编排层一次探活依赖。 否决。存活与就绪探针分离；数据库抖动时不要整体重启容器。业务接口返回 503。

本步要核对

核对项 本迭代应采用 怎么查（规约 / 代码 / 运行） 自检
/health 是否混入数据库探活？ 只做存活判定；数据库不可用由业务接口返回 503，不判为会话失效。 规约：design.md D9 与 specs/auth-upload/spec.md R8（/health）
代码：看 health handler 是否查询数据库
运行：停掉 db，对比 /health 与 /api/materials 的返回

动手要做

  • 数据库只在 Compose 内部网络可达，不要映射宿主端口。
  • 本地用 Docker Compose 构建与启动；当前单实例，多副本方案本迭代不做。
