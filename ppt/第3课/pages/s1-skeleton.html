1目录骨架与配置外置

先让能编译、能构建、能读配置的骨架运行起来；配置只从环境读，仓库里只留示例文件。

知识点

配置外置

密钥、数据库口令、种子口令只来自环境。源码和镜像里不放真实值。.env 不入库，.env.example 必须入库，第三方才能复现。

其他可行方案与选择依据

方案 要点 本课如何取舍
YAML / TOML 配置文件入库 结构清晰，易配多环境。 密钥仍须环境变量覆盖。本课以 .env + 环境变量为主，避免把口令写进 YAML。
前后端一个仓库一个进程 目录结构简单。 可行。当前需求拆分为 frontend / backend，Compose 三服务，便于后续单独扩展 api 服务。

本步要核对

核对项 本迭代应采用 怎么查（规约 / 代码 / 运行） 自检
缺配置时是启动失败，还是落到内置默认值？ 失败即停，不内置任何默认密钥。 规约：specs/auth-upload/spec.md R7.3 与 design.md「配置与启动」
代码：搜默认值常量与配置回退逻辑
运行：删除 .env 后执行启动命令，应报错退出
.env.example 是否足以让第三方复现？ 列出全部必填项，且不含真实值。 规约：tasks.md §1.3–1.4 与 proposal.md Impact
代码：比对代码读取的环境变量与 .env.example 条目
运行：只按 .env.example 填写后能否启动成功

动手要做

  • 后端：backend/cmd/server，以及 internal/{config,db,auth,materials,knowledge}。
  • 前端：Vite 初始化 React + TypeScript，预留登录页与材料页。
  • 配置来自环境变量：SESSION_SECRET、数据库凭据、上传目录与上限、会话 TTL（Time-To-Live，有效期）、预置账号口令、登录失败阈值。密钥缺失则启动失败。

2密钥缺失即启动失败，且不进仓库与镜像

内置默认密钥等于把会话标识的签发权交给任何人；镜像里能进的东西就可能被分发。

知识点

失败即停

SESSION_SECRET 或数据库凭据缺失时启动失败，禁止静默落到内置默认值。内置默认密钥意味着任何人都有可能伪造会话标识。

镜像卫生

.dockerignore 避免把 .env 和 uploads 打入镜像。进入镜像的内容都有可能被分发出去。

其他可行方案与选择依据

方案 要点 本课如何取舍
启动时内置开发默认密钥 克隆仓库后即可运行。 否决。第三方复现必须显式填写 SESSION_SECRET。

本步要核对

核对项 本迭代应采用 怎么查（规约 / 代码 / 运行） 自检
仓库里有没有真实密钥？ 无。.env 不入库，.env.example 必须入库。 规约：配置外置要求
代码：看 .gitignore 与实际入库文件清单
运行：克隆到干净目录，搜有无可用密钥
.dockerignore 是否排除 .env 与 uploads/？ 排除，避免密钥与数据进入镜像。 规约：镜像卫生要求
代码：看 .dockerignore 与 Dockerfile 的 COPY 范围
运行：构建镜像后检查镜像内是否含 .env

动手要做

  • 提交 .env.example、.gitignore、.dockerignore，排除 .env 与 uploads/。

3开工前：确认 change 状态并复述范围

让实现从规约出发而不是从记忆出发：先确认 change 状态，再让 Harness 复述范围与 Non-goals。

开工前先确认 change 的状态

第 2 课留下的是「四件套齐全、待办全空」的规约。开工前确认三件事，再让 Harness 开始实现：openspec list 里本 change 是唯一的活动变更；四件套齐全且 tasks.md 全部未勾选；openspec/specs/ 里还没有本能力。核对路径：openspec/changes/<change>/proposal.md（Non-goals）、design.md（技术栈与 Decisions）、specs/auth-upload/spec.md（Scenario）、tasks.md（verify）。

确认完再复述范围：把 change 目录路径交给 Harness，让它先复述本迭代范围与 Non-goals，复述有误就当场纠偏，不要带着错误理解开始写代码。

本步要核对

核对项 本迭代应采用 怎么查（规约 / 代码 / 运行） 自检
Harness 会话有没有先复述范围与 Non-goals？ 先复述再生成，避免直接开到全站。 规约：实现流程要求
代码：回看对话记录的开头
运行：复述内容与本人规约范围是否一致

动手要做

  • 新开 Harness 会话，给出规约路径，先让它复述范围与 Non-goals，再 /opsx-apply。

把否决理由用自己的话写进 design / 迭代说明；原文照录本表不算 ADR。

向 Harness 核对的参考提问

可直接复制到会话中使用。要求它逐项给出证据（文件与行号、命令与输出），找不到就明说、不许推测；回答只作线索，勾选前仍须亲自运行 verify 复核。

  1. 通读启动代码，列出全部配置项及其读取位置（文件与行号），指出是否存在硬编码密钥或内置默认值；逐项说明缺省时是启动失败还是落到默认值。
  2. 实际演示缺失 SESSION_SECRET 时的启动行为，把输出贴出来，并指出决定该行为的代码分支。
  3. 对照 .env.example、.gitignore 与 .dockerignore：第三方能否仅凭示例文件复现配置？仓库与镜像构建上下文是否可能带入真实密钥或本地上传文件？
  4. 复述你理解的本次任务范围与 Non-goals，我来核对你是否漏掉了边界。
