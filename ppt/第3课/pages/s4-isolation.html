4 班级隔离

班级是数据边界。这是本课核心：单库多租户如何防止水平越权。

1集合路径：列表只查本班

租户条件只来自服务端会话；请求里带的 class_id 一律忽略。

知识点

不信任客户端租户标识

query、Header、表单中的 class_id 都属于攻击者可控的输入。租户标识只取自会话。采信请求中的班级，相当于把隔离判定权交给调用方。

2对象路径：先取行再校验

知道对象 ID 不等于有权访问。详情与文件必须独立核对归属，前端拦截不算数。

知识点

BOLA / IDOR

Broken Object Level Authorization：知道对象 ID 就能越权读取其他班级的材料。攻击者与受害者同角色、不同租户。列表过滤正确，按 ID 取详情或文件的路径仍可能遗漏校验。

先取行再校验（fetch-then-check）

按 ID 先取出行，再核对归属。与列表上的 WHERE class_id = 会话班级是两条独立路径，必须分别设计、分别验收。

  • 教师上传时即使表单带其他班级字段，新建的材料与知识库条目仍归属会话所在班级。

3跨班返回 403 还是 404

401 与 403 会泄露账号或资源的存在性；本需求采用 404，并保证全文一致。

知识点

403 与 404

403 明确告知资源存在但没有权限，利于排障，也利于枚举。404 让越权访问与资源不存在返回完全相同的响应，从而隐藏资源存在性，排障改走服务端审计日志。必须择一、全文一致、写进 README。本需求采用 404。

其他可行方案与选择依据

方案 要点 本课如何取舍
跨班返回 403 排障方便，调用方可以确认资源存在。 否决作为本需求默认。会泄露资源存在性，便于遍历扫描资源 ID。选 404，并在日志中记录跨班访问。
跨班返回 401 要求用户重新登录。 否决。用户已认证，问题属于对象级授权，不是未登录。
