要做成什么样

对照迭代 1 的产品目标与 OpenSpec 可验收范围。以本人学期仓规约为准：能力不少于 spec 的 Requirement/Scenario；未写入规约的体验条目属产品愿景，不必做（分层见本页第 3、4 节）。Apply 起点：project-src/week03/；完成对照：project-src/week03-applied/。

每步按同一顺序展开：知识点 → 其他可行方案与选择依据 → 本步要核对 → 动手要做。“怎么查”一列给出三处证据：规约读哪条、代码搜什么、运行做什么；发现不一致，先补规约或改实现。全课汇总见 实现方案核对总表。

1账号与角色：谁能做什么

本迭代只实现教师与学生两种角色的权限；平台超级管理员是产品完整形态里必然存在的角色，但不在本迭代。能力边界要写成可判定的要求，而不是界面上看不看得见。

知识点

最小权限

教师可上传、查看、下载；学生只能查看和下载。多给的能力就是垂直越权面。角色来自服务端会话，不来自前端切换。

其他可行方案与选择依据

方案 要点 本课如何取舍
三角色：管理员 / 教师 / 学生 管理员跨班运维方便。 本迭代不做，推迟到后续迭代：超级管理员天然跨班，会与“跨班返回 404”的隔离验收直接冲突。隔离验收通过后再单独设计它的越权路径与操作审计。

本步要核对

核对项 本迭代应采用 怎么查（规约 / 代码 / 运行） 自检
角色与能力边界是否逐条写成可判定的要求？ 教师＝上传/查看/下载；学生＝查看/下载。多给一项能力就多一个垂直越权面。 规约：Requirement 中每个角色各有哪些 Scenario
代码：搜角色常量与权限判断分支，看学生分支是否出现写操作
运行：分别用教师与学生账号各试一次上传

动手要做

  • 账号密码登录；角色只有教师与学生。
  • 教师可上传、查看、下载本班材料；学生只能查看和下载。
  • 身份、角色、班级由服务端会话识别，不信任客户端自行声明。

2班级：数据边界从哪里来

每个用户属于固定班级，班级取自服务端会话，不能由请求参数决定。

知识点

班级是租户边界

在同一个数据库实例中用 class_id 划分班级数据边界。用户属于固定班级，不能通过请求参数切换班级。这是多租户数据隔离，不是前端菜单过滤。

其他可行方案与选择依据

方案 要点 本课如何取舍
以学校或课程为租户 更接近最终产品。 本课租户是班级，边界清晰，种子两班即可验收。

本步要核对

核对项 本迭代应采用 怎么查（规约 / 代码 / 运行） 自检
班级边界是写进规约，还是只写在 design 里？ 必须作为 Requirement 的 Scenario 出现，隔离失败才有判定依据。 规约：跨班访问是否写成可判定的 Scenario
代码：对比 spec.md 与 design.md 中关于 class 的描述层级
运行：按 Scenario 逐条跑失败路径，看是否都能判通过与否

动手要做

  • 每个用户属于一个固定班级。
  • 只能访问自己班级的材料；跨班由服务端拒绝。

3材料与知识库：本迭代做到哪一步

材料上传、提取正文、本班可查；知识库本课只负责存正文，不做问答。

知识点

知识库本课只负责存

上传后提取正文写入可查询的数据行，为后续检索预置数据。本班列表搜索可以做；向量检索、问答与 RAG（Retrieval-Augmented Generation，检索增强生成）不是本迭代的范围。

其他可行方案与选择依据

方案 要点 本课如何取舍
本课直接做 RAG / 问答 演示效果强。 否决。没有可靠的入库与隔离，检索会造成跨班数据泄露。本迭代的知识库只负责存储正文。
列表硬编码演示数据 前端实现最快。 否决。必须从数据库查询，否则上传与隔离无法验收。

本步要核对

核对项 本迭代应采用 怎么查（规约 / 代码 / 运行） 自检
Non-goals 是否写明检索、问答、作业不做？ 必须写明。缺失时 Harness 最容易越界生成整块功能。 规约：proposal.md 的 Non-goals（明确不做项）章节
代码：搜依赖清单与路由，看有无向量库、对话接口
运行：让 Harness 复述范围，观察是否夹带不做项
列表与搜索的数据来源是否写明？ 必须来自按班级过滤的数据库查询，不得硬编码演示条目。 规约：列表中是否写明数据来源与过滤条件
代码：搜列表 handler，看查询语句是否带 class_id
运行：清空材料表后刷新列表，应无任何条目
上传校验与失败状态是否可判定？ 扩展名、大小、内容三类失败各有明确状态码，且数据库与磁盘无残留。 规约：是否有对应 Scenario 与预期状态码
代码：搜校验分支与错误返回位置
运行：分别上传 .exe、超限文件、非法编码文件各一次

动手要做

规约必做（演示 change：specs/auth-upload/spec.md R4–R5、R9、R10）：

  • 教师上传 .txt / .md；解析正文并在同事务内写入 materials 与 knowledge_entries（R4）。
  • 本班列表由数据库按会话班级过滤；详情与文件经鉴权 API（R3、R5、R9.4），不得静态暴露 /uploads。
  • 上传须校验扩展名与大小上限；解析/入库失败时两表与磁盘均无残留（R4.4–R4.7）。
  • Web：登录页 + 材料页；/api/me、401 回登录、正文安全（R9）；北大红品牌、深浅色、列表/网格、本班搜索、命令面板、上传进度、toast、Markdown GFM（R10）。

明确不做（proposal.md Non-goals，写了也不能当必做验收）：

  • 跨班检索、向量检索、RAG 问答（本班前端筛选不算跨班检索）。

4页面体验：可选增强，不能替代鉴权

体验可以写进规约并逐条验收，但不能替代服务端 RBAC 与班级隔离；未写入规约的体验条目不必做。

动手要做（可选，先写进规约再做）

  • 操作结果用通知或页内错误提示反馈（登录失败须统一文案，R1.2）。
  • 其余视觉与交互（北大红、深浅色、双视图、命令面板、移动端适配等）按本人产品规约取舍。
列表数据必须来自数据库查询，不要硬编码演示条目。前端「搜索」若实现，只能在本班已加载/已查询的数据范围内过滤，不是第 4 课的全文检索。

把否决理由用自己的话写进 design / 迭代说明；原文照录本表不算 ADR。

想一想：判断与取舍

先对照本人规约作答。引用不到原文，先改规约再写代码。

  • 教师上传后本班学生可见，这是授权问题还是列表查询来源问题？缺其一，后续检索会在哪一环节失效？
  • Non-goals（明确不做项）是否写明检索、对话、作业不做？缺失时最容易额外生成哪些越界功能？
