# 第 4 课：可追溯知识库检索

> 来源：北京大学《互联网软件开发技术与实践》第 4 课课件（HTML 整理为 Markdown）

## 实现教程

第 3 课已实现登录、按班级隔离以及教研材料入库。本课在同一套系统上增加检索能力：以一句自然语言在本班材料中定位相关片段，并标注其来自哪份材料的哪一个切片。当资料中不存在依据时，应明确返回未找到，不得编造出处。

### 1. 本课承接第 3 课

登录、角色校验与上传入库沿用第 3 课的实现，本课不再重做。本课对应的 change 为 `add-traceable-vector-retrieval`。

### 2. 先记住三条结论

#### 切片正文存于 MySQL，向量存于 Qdrant

切片文本存放于 `knowledge_chunks` 表；向量库中仅保存浮点向量与若干标识，向量主键与 `knowledge_chunks.id` 相同。检索时先命中向量记录，再回 MySQL 取回切片正文。

#### 三种检索模式回答的不是同一类问题

关键字检索匹配原文中出现的词；向量检索匹配表述不同但语义相近的内容；混合检索先分别排序，再用 RRF 融合为最终次序。默认采用混合模式。

#### 无依据时不得凑数

所选模式过滤后若无候选切片，即返回「资料中未找到相关内容」。班级标识仅从登录会话读取，请求中自带的班级编号一律无效。

- **本课目标与范围**：切分、三类检索模式、出处标注与无依据处理
- **RAG 原理与技术选型**：检索增强生成的原理，以及本课的技术选型
- **检索链路与模块协作**：入库四步；三类检索各自访问的组件
- **切分策略选择**：自动窗口、自定义分隔符、按标题分章
- **检索侧的班级隔离**：班级取自会话；关键字与向量两条路径均须过滤
- **回答生成与引用标注**：有命中切片才生成回答；无切片不调用模型
- **思考与分析**：检索现象分析，以及两库的数据形态与关联方式

## 本课目标与范围

学生与教师均可检索本班材料；上传仍仅限教师角色。范围判定以 `week04` 中的 `knowledge-retrieval` 规约（spec）为准。

### 1. 先将正文切分为切片

上传成功后，正文被切分为若干切片再进行向量嵌入。默认按约 800 字的窗口切分，相邻切片允许重叠；也可按换行、空行或句号切分，或依 Markdown 标题分章。种子材料启动时仍采用默认窗口策略。

### 2. 三种检索模式的适用场景

| 模式 | 适用场景 |
| --- | --- |
| `keyword` | 问句中的词直接出现在原文中。仅查询 MySQL 全文索引，不调用嵌入服务。 |
| `vector` | 表述改变但语义保留。问句先转换为向量，再与切片向量计算余弦相似度；低于 0.35 的候选不予保留。 |
| `hybrid` | 同时执行两条路径，按名次融合排序。两路均命中的切片排序更靠前。 |

### 3. 每条结果均须可回溯至原文

命中结果至少应给出材料标题、切片序号、字符区间与一段摘录，并支持打开对应材料。摘录取自 MySQL 中的切片正文，而非向量库。

> 当提问内容与本班材料无关时，返回「资料中未找到相关内容」，`hits` 为空。不得以相关度明显偏低的切片凑数。

## RAG 原理与技术选型

RAG（Retrieval-Augmented Generation，检索增强生成）先从资料中检索依据，再让生成模型依据这些证据作答。本课实现简短回答：仅当存在命中切片时才调用生成模型，并标注出处。流式长对话安排在第 5 课。

### 1. RAG 解决什么问题

#### 模型记忆中的知识，不等同于你的资料

大模型的参数中并不包含本校讲义，却仍可能把未见过的问题回答得煞有介事。RAG 的做法是：提问时先检索本班材料，将命中的切片连同出处一并交给模型，使回答能够回溯到原文。若未检索到依据，则不应生成任何内容。

1. **1 切分**：长文切分为切片
2. **2 嵌入**：文本转换为向量
3. **3 入库**：正文入关系库，向量入向量库
4. **4 检索**：关键字、向量或混合检索
5. **5 生成**：有切片才生成简短回答

> 先检索，再生成。当本班材料中不存在依据时，不将问题提交给生成模型。
> 图中标注：提问 / 只用这一句 / 检索本班切片 / 关键字、向量或混合 / 有切片 / 连同编号一并交给模型 / 简短回答 / 正文以 [1] 标注出处 / 没有切片 / 返回「资料中未找到相关内容」，不调用生成模型

### 2. 主流技术方案与本课选型

| 环节 | 常见技术 | 本课选型 |
| --- | --- | --- |
| 切分 | 固定窗口、按分隔符、按标题层级；亦有按句子或语义边界切分的方法 | 自动窗口、自定义分隔符、Markdown 标题；默认约 800 字，重叠约 10% |
| 嵌入 | 调用兼容 OpenAI `/embeddings` 接口的嵌入模型，得到固定维度的浮点向量 | 仅在服务端调用课程网关；向量维度与 Qdrant collection 保持一致，密钥不下发到浏览器 |
| 向量库 | Qdrant、Milvus、pgvector、Chroma、Weaviate 等，相似度度量多采用余弦距离 | Compose 中的 Qdrant；集合 `campusclaw_chunks`，度量方式为余弦 |
| 关键字 | 倒排索引。英文常用 BM25；中文须借助 ngram 或分词器，否则全文索引无法正确切词 | MySQL `FULLTEXT ... WITH PARSER ngram`，token 长度为 2 |
| 混合排序 | 分数加权求和，或 RRF（Reciprocal Rank Fusion，倒数排名融合） | 两路先按绝对分数过滤，再执行 RRF（`k = 60`）。名次分不是相关性阈值 |
| 重排序 | 使用交叉编码器对前若干条候选重新打分，通常比单次向量检索更准确，但延迟更高 | 本课不实现 |
| 编排框架 | LangChain、LlamaIndex，以及 Dify 一类带可视化界面的知识库产品 | 不引入框架。由 Go 服务自行完成切分、向量嵌入与检索，便于对照规约逐条验收 |

> 切片正文保留在 MySQL，向量库仅保存向量与若干标识。向量主键等于 `knowledge_chunks.id`——这是本课的关联方式，而非将整段原文重复存入 Qdrant。

> 嵌入与对话是两个独立模块、两次不同的调用。学生须区分「将文本转换为向量」与「依据切片撰写回答」这两件事。
> 图中标注：嵌入模块 / 输入：一段切片或问句 / 输出：一条向量 / 入库与向量检索时使用 / 关键字检索不调用该模块 / 对话模块 / 输入：材料标题、切片正文与问题 / 输出：带 [1] 标注的简短回答 / 仅在已检索到切片之后触发 / 没有依据时不触发该模块 / 浏览器 / 只调用本站 /api / 不持有网关密钥 / 页面中不展示向量分量

## 检索链路与模块协作

浏览器仍然只访问本站的 Go 接口。第 3 课的认证模块与材料模块继续生效；本课在其后追加切分、向量嵌入、向量库与对话模块。嵌入网关与 Qdrant 均位于服务端，班级编号仅从登录会话读取。

### 1. 新增模块的位置

第 3 课已包含浏览器、Nginx、认证模块、材料模块与 MySQL。本课沿用既有链路，仅在材料上传成功之后，由检索模块将正文转换为可检索的切片。

> 客户端无法直连 Qdrant，也无法直连两类模型网关。它们仅接受 Go 中检索模块发起的调用，密钥不会下发到页面。
> 图中标注：浏览器 / 只访问本站 / Nginx / /api 反向代理至 Go / Go / 认证模块（请求先经此处） / 材料模块（文件与正文） / 检索模块 / 切分 · 检索 · 回答编排 / MySQL / 会话、正文与切片文本 / Qdrant / 仅存向量与编号，不含正文 / 两类模型网关 / 嵌入：文本 → 向量 / 对话：有切片时才调用

#### 两类网关不是同一个模块

嵌入网关将一段文本转换为固定维度的浮点向量，在入库与向量检索时使用。对话网关读取切片正文并生成简短回答，仅在问答接口已取得依据之后才被调用。关键字检索不触及二者；没有命中切片时，对话网关也不会被触发。

### 2. 上传时的入库流程

1. **1 保存原文**：材料文件与 `knowledge_entries.body_text`
2. **2 切分**：按本次策略写入 `knowledge_chunks`
3. **3 嵌入**：每个切片转换为一条向量
4. **4 写入 Qdrant**：向量主键与切片主键一致

向量库的 payload 仅包含 `class_id`、`material_id`、`knowledge_entry_id`、`chunk_id`、`chunk_index`，不含正文。嵌入失败时材料记录仍然保留，对应切片标记为 failed，不写入不完整的向量数据。教师可按新策略重建索引：先删除旧切片与旧向量记录，再重新写入。

> 材料模块先保留原文。检索模块失败时原文仍然存在，仅这批切片无法用于向量检索。
> 图中标注：材料模块 / 文件 + 正文 / 事务已提交 / 切分 / 读取 body_text / 不改写原文 / MySQL 切片 / 先删除旧切片 / 再写入新记录 / 嵌入 / 每段一条 / 向量 / Qdrant / 向量主键 / = 切片主键

### 3. 检索时的三条路径

| 模式 | 访问的组件 | 排序方式 |
| --- | --- | --- |
| `keyword` | 仅查询 MySQL 全文索引；不调用嵌入服务，也不访问 Qdrant | 按全文相关度由高到低 |
| `vector` | 问句先做向量嵌入，再在 Qdrant 中按 `class_id` 过滤；余弦相似度低于 0.35 的候选丢弃；随后以向量主键回 MySQL 取回正文 | 按余弦相似度由高到低 |
| `hybrid` | 同时执行上述两条路径 | 各路先独立过滤，再按名次执行 RRF（`k = 60`）；缺席的一路不贡献分数 |

> 摘录始终取自 MySQL 的 `chunk_text`。Qdrant 不可用时，关键字检索仍可返回结果；向量与混合模式返回 503，不编造相似度分数。空查询返回 400。

> 三条路径最终都回到 MySQL 取回正文，Qdrant 中不保存正文。混合检索融合的是两路的名次，而非将分数相加。
> 图中标注：关键字 / 只查 MySQL 全文索引 / 按全文相关度由高到低 / 向量 / 问句向量嵌入 / Qdrant 按班级过滤 / 余弦低于 0.35 的候选丢弃 / 回 MySQL 取回正文 / 向量主键 = 切片主键 / 混合 / 两条路径均执行，各路先过滤，再按名次执行 RRF / k = 60；缺席的一路不贡献分数

#### 问答接口再引入一个模块

`POST /api/ask` 自身不实现第三种检索。它先由检索模块以混合模式取回本班前 4 条切片；若一条都没有，则在检索模块处直接返回固定文案，对话网关不会被调用。存在命中切片时，对话模块收到的是材料标题、切片序号与切片正文，以及用户本轮提问；它不会获得向量分量，也不会获得其他班级的材料。

## 切分策略选择

切片是检索的最小单位。切分过长，单个切片会混入多件互不相关的事；切分过短，则一个完整句子会被拆散。上传与重建索引使用同一组参数；未指定策略时按自动切分处理，种子材料启动时补齐索引同样采用自动切分。

### 1. 三种策略

| 策略 | 适合 | 规则 |
| --- | --- | --- |
| `auto` | 讲义、规章制度一类常规正文 | 最大 800 字，重叠 80 字；优先在空行、换行、句号处断开。请求中另行填写的长度与预处理参数不生效 |
| `custom` | 希望按换行、空行或句号控制粒度 | 最大长度 100 至 2000 字，重叠比例 0% 至 50%；无断点处按最大长度强制截断。可预先移除 URL 与邮箱，或将连续空白折叠为单个空格 |
| `hierarchy` | 含 Markdown 标题的课程资料 | 按 `#`、`##`、`###` 层级分章，标题保留在该章切片内；某章过长时，再按自动窗口规则切分 |

> 三种策略作用于同一份正文。未指定策略时按自动窗口处理，种子材料补齐索引亦采用该策略。
> 图中标注：自动窗口 / 切片 1 约 800 字 / 切片 2 与上一切片重叠 / 优先在空行、换行、句号断开 / 自定义分隔符 / 第一句。 / 第二句。 / 无断点处按长度强制截断 / 长度 100–2000，重叠 0–50% / 按标题分章 / # 第一章 整章保留在同一切片 / ## 过长时再按窗口切分 / 标题保留在该章切片内

#### 切分模块的输入与输出

输入为知识库正文 `body_text`，以及本次请求指定的策略；输出为若干条切片，包含切片文本、序号及其在待切分文本中的位置。原始文件与 `body_text` 保持上传时的原样。切分模块不调用嵌入服务，也不写入 Qdrant；这两步在其返回之后由检索模块继续执行。

### 2. 两处易混淆要点

#### 预处理不改写原文

移除链接、折叠空白等预处理仅作用于待切分与待嵌入的文本。`knowledge_entries.body_text` 仍为上传原文。此时切片偏移量是相对于预处理后文本计算的，不能再视作原文件中的字符下标。

#### 切换策略须重建索引

已入库材料不会自动重新切分。重建索引采用的是本次请求中的策略，而非上传时使用的策略。若已将连续空白折叠为空格，则换行符不复存在，再以换行作为分隔符将无法切分。

## 检索侧的班级隔离

检索与上传共用同一条班级边界。学生与教师均可检索本班材料，且都不能通过修改请求看到其他班级的内容。前端隐藏入口不构成隔离，过滤必须发生在服务端。

### 1. 班级标识仅取自会话

登录之后，会话中已存有该用户的 `class_id`。检索接口被调用之前，认证模块已依据 Cookie 将该用户写入请求上下文。检索模块只从该上下文读取班级；查询字符串、JSON 正文或请求头中另行携带的班级编号，在解析后一律丢弃。

> 以 A 班身份登录后，即便在请求体中写入 B 班的 `class_id`，实际过滤条件仍是 A 班，结果中不得出现 B 班的切片。

> 仅在单侧过滤并不充分。关键字与向量两条路径都须使用会话中的班级，且在回表查询时再次核对。
> 图中标注：请求中携带的 class_id / 解析后即丢弃 / 会话中的 class_id / 登录时已写入 / 仅使用该值 / 查询参数一律无效 / MySQL / WHERE class_id = 会话班级 / Qdrant / 同样按 class_id 过滤

### 2. 两条路径均须携带班级条件

| 路径 | 怎么限定 |
| --- | --- |
| 关键字 | MySQL 查询条件包含 `class_id = 会话班级`，且仅检索 `index_status = ready` 的切片 |
| 向量 | Qdrant 查询须带 `class_id` 过滤；返回向量主键后，再用同一班级条件回 MySQL 取回正文。payload 中的编号不得单独作为正文来源 |

仅在单侧过滤并不充分。即便向量库漏加过滤条件，回表时的班级约束仍应将其他班级的记录排除在外。

### 3. 跨班级检索对外表现为无命中

使用仅存在于 B 班正文中的词，在 A 班发起检索，响应应为 HTTP 200、空的命中列表，或「资料中未找到相关内容」。不应以 403 或 404 向调用方暗示「该资料属于其他班级」。按材料标识打开详情仍沿用第 3 课规则：跨班级与不存在均返回 404。

## 回答生成与引用标注

问答并非让生成模型自由发挥。系统先对用户当前这句话执行本班混合检索，只有命中切片之后，才将这几段交给模型撰写简短回答。

### 1. 先检索，再生成

1. **1 问题**：仅以最新一句发起检索
2. **2 混合检索**：限定本班，取前 4 条
3. **3 有切片**：连同编号一并交给模型
4. **4 回答**：回答中以 [1] 指回出处

模型获得的是材料标题、切片序号与切片正文，而非向量分量。页面上展示的出处列表与回答中的 [1]、[2] 标注顺序一致。

> 生成模型仅在已取得本班切片之后才被调用。天气、比分一类问题不会被模型以参数记忆勉强作答。
> 图中标注：用户本轮提问 / 历史对话附于其后 / 本班混合检索 / 取前 4 条 / 有切片 → 调用生成模型 / 回答中的 [1]、[2] 与出处列表顺序一致 / 无切片 → 不调用生成模型 / 返回固定文案，citations 为空

### 2. 无命中切片时不调用生成模型

混合检索无候选结果时，接口直接返回「资料中未找到相关内容」，citations 为空。此路径不访问对话网关，以避免模型凭借参数记忆将天气、比分一类的问题勉强作答。

> 此前若干轮对话可附于其后，便于连续追问。班级仍仅从会话读取。客户端注入的 system 消息会被丢弃。本课不实现流式输出。

> 对话模块的输入由检索模块组装。它不得自行访问数据库或向量库检索其他材料。

## 思考与分析

### 1. 关键字、向量与混合检索分别访问哪些组件？Qdrant 是否对客户端暴露？

#### 现象观察与验证

分别使用原词与同义改写，请求 `keyword`、`vector`、`hybrid` 三种模式，并对照 `query_vector`、两路 `score` 与 `rank` 字段。使用原词时应有关键字命中且不产生问句向量；改写后关键字路径落空，向量路径仍可能命中。请求主机为本站 `/week04/api`。停止 Qdrant 后，关键字检索仍可返回正文，向量与混合模式返回 503。

#### 设计含义

关键字检索判断词是否出现，向量检索判断语义是否接近。全文相关度与余弦相似度不能直接相加；混合模式按名次执行 RRF（`k = 60`），缺席的一路不贡献分数。Qdrant 不对外开放，班级过滤与回表查询均保留在服务端。

#### 替代方案与权衡

分数归一化后加权求和，但更换嵌入模型需重新标定权重。仅保留混合模式时，一旦向量库故障，关键字路径便无法单独降级使用。引入交叉编码器重排序更准确，但延迟更高。若将 Qdrant 端口映射出来便于调试，客户端即可绕过认证直接访问。

> 客户端仅调用本站检索接口。Qdrant 与两类模型网关均不作为浏览器入口。
> 图中标注：关键字 / 只查 MySQL 全文索引。不调用嵌入，不访问 Qdrant / 向量 / 问句嵌入 → Qdrant 按班级过滤 → 向量主键回表取正文 / 混合 / 两条路径均执行，过滤后按名次执行 RRF，而非分数相加

### 2. 在请求中修改 `class_id`，能否检索到其他班级的切片？

#### 现象观察与验证

以 A 班会话检索一个仅出现在 B 班正文中的词，第二次在请求体中写入 B 班的 `class_id`。两次响应均应返回 200 且 `hits` 为空，问答接口返回固定文案。以该会话打开 B 班材料详情，结果与不存在的标识一样为 404。

#### 设计含义

班级取自会话，请求体中的 `class_id` 被丢弃。对外表现为无命中，从而避免以 403 泄露资料归属于其他班级。MySQL 与 Qdrant 使用同一会话班级值值；仅在单侧过滤时，另一侧仍会返回其他班级的候选。

#### 替代方案与权衡

改为返回 403 虽可区分「无权访问」与「资源不存在」，但会泄露资源存在性。按班级拆分 Qdrant 集合可强化隔离，但集合数量随之增加。即便采用数据库行级安全策略，传入的班级值仍必须来源于会话。

> 跨班级检索对外表现为无命中，而非 403。仅在单侧添加班级条件时，另一侧仍可能返回其他班级的候选。
> 图中标注：请求体中的 class_id / 解析后丢弃 / 会话中的 class_id / 认证中间件已写入请求上下文 / 只使用该值 / MySQL 查询条件 / class_id = 会话班级 / Qdrant 过滤条件 / 同一会话班级值

### 3. 语料中不存在依据时，是否仍调用生成模型？

#### 现象观察与验证

材料中确有依据的问题，其 `[1]`、`[2]` 标注与 `citations` 顺序一致。材料中不可能出现的问题（如天气、比分）仍返回 200，正文为固定文案，`citations` 为空。该固定文案由接口在检索之后直接返回。请求中携带的 `system` 消息应被丢弃。

#### 设计含义

若在无切片情况下仍调用生成模型，回答将依赖训练记忆，无法回溯至本班材料。存在命中切片时，`system` 提示由服务端写入，仅允许模型依据编号对应的资料作答。

#### 替代方案与权衡

在无依据时仍调用模型并要求其声明「不知道」，提示约束可能被忽略。若改为返回 404，则会将空结果与资源不存在混为一谈。若将弱相关候选一并送入模型，回答的可追溯性会随之下降。

> 无命中时，请求在检索之后即结束。页面上出现文字，并不能证明生成模型被调用过。
> 图中标注：最新一条提问 / system 消息被丢弃 / 本班混合检索 / 取前 4 条 / 有切片 → 调用生成模型 / [1]、[2] 与出处列表顺序一致 / 无切片 → 不调用生成模型 / 固定句，citations 为空

### 4. 三种切分策略的输入分别是什么？更换策略后既有切片是否保留？

#### 现象观察与验证

取同一份带标题的材料，分别以三种策略各重建一次索引。先记录切片条数与向量主键。若未重建，则旧切片仍然存在；未指定策略时等同于自动窗口（约 800 字，重叠 80 字）。预处理之后 `body_text` 仍为原文，切片偏移对应的是预处理后的文本。

#### 设计含义

切片是检索的基本单位；重叠用于避免句子被截断在窗口边界。重建索引时先删除旧切片与旧向量，避免遗留过期主键。原文不随预处理发生改写。

#### 替代方案与权衡

按句子或语义边界切分，切片长度不稳定。采用「子切片负责检索、父块送入模型」的方案需额外一次回表查询。仅对变更段落重新嵌入，则须具备判断哪一段发生变化的能力。

> 已入库材料不会自动重新切分；更换策略必须显式重建索引。
> 图中标注：删除旧数据 / 旧切片与旧向量记录 / 按本次策略切分 / 未指定时按自动窗口处理 / 写入新切片 / 随后嵌入并写入向量 / 不改原文 / body_text 仍是上传原文 / 预处理只作用于切分输入

### 5. MySQL 与向量库各存什么形态的数据？二者如何关联？

#### 现象观察与验证

取同一条切片对照两侧存储。MySQL 中保存 `body_text`、`chunk_text` 与字符偏移；Qdrant 中保存定长浮点向量，payload 仅含若干标识。向量主键、`knowledge_chunks.id` 与 `payload.chunk_id` 三者应相同。嵌入失败时 MySQL 记录仍然存在，向量库中无对应记录。

#### 设计含义

正文保留在 MySQL，关键字检索与结果摘录均不依赖 Qdrant。主键一致即可直接回表查询，无需在向量库中重复保存一份字符串。

#### 替代方案与权衡

将 `chunk_text` 写入 payload 可减少一次查询，但正文将存在两份副本。向量主键改用随机标识再建立映射，回表前需多一次查找。若将全文索引并入同一检索引擎，班级过滤与事务一致性设计都需重做。

> 摘录取自 MySQL 的 chunk_text 字段。向量库中不含该字符串，仅凭同一主键指回对应数据行。
> 图中标注：MySQL · 关系行 / 形态：字符串 / body_text：上传原文 / chunk_text：切片正文 / 班级、条目、序号、字符偏移 / 全文索引建立在 chunk_text 上 / Qdrant · 向量记录 / 形态：定长浮点向量 / 度量：余弦 / payload：仅含标识 / 班级、材料、条目、切片、序号 / 不含 chunk_text / 关联：向量主键 = knowledge_chunks.id = payload.chunk_id
