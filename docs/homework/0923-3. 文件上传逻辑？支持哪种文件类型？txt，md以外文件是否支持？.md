# 0923-3. 文件上传逻辑分析

## 一、上传链路（服务端 `POST /materials/upload`）

```
教师浏览器 (multipart/form-data)
        │
        ▼
① 登录校验：无会话 → 302 到登录页（页面）/ 401（API）
② 角色校验：非 teacher → 403 拒绝（学生上传实测返回 403，且 DB 与上传目录零变化）
③ 文件校验：未选择文件 → 400；扩展名不在白名单 → 400
④ 落盘：文件名清洗（取 basename、剔除 ".."）后加 UUID 前缀，
        存到 uploads/{class_id}/ 目录 —— class_id 只取自服务端会话，表单无法指定
⑤ 解析：按 UTF-8 读取全文；读取失败 / 内容为空 → 删除已落盘文件，返回 400，不写任何 DB 记录
⑥ 入库（单事务）：BEGIN
        INSERT materials (标题、class_id、文件名、路径、上传者)
        INSERT knowledge_entries (material_id、class_id、正文文本)
        COMMIT → 任一步失败整体回滚
⑦ 本班材料列表查库展示，上传后刷新即可见新记录（同班学生可见但只读）
```

设计要点：

- **解析失败不产生脏数据**：先删文件再返回，DB 零写入
- **两表写入同事务**：不会出现"材料有记录但知识库没有"的中间态
- **班级归属只信会话**：`class_id` 从 session 取，防止越权代传到别班

## 二、支持的文件类型

**当前仅支持 `.txt` 和 `.md` 两种**，通过服务端扩展名白名单控制：

```python
ALLOWED_EXTENSIONS = {".txt", ".md"}
```

另有 5 MB 大小上限（Flask `MAX_CONTENT_LENGTH`）。

## 三、txt、md 以外的文件是否支持？

**不支持，这是有意的设计决策而非遗漏。** 上传其他类型（如 `.exe`、`.pdf`、`.docx`）时：

1. 服务端在校验阶段直接返回 **HTTP 400「仅支持 .txt / .md 文件」**
2. 不会落盘、不会在 materials / knowledge_entries 两表留下任何记录（实测上传 `.exe` 后 DB 行数与上传前完全一致）

原因（design.md Decisions 第 5 条）：MVP 阶段解析器只实现"按纯文本读取"，txt/md 可直接按 UTF-8 解析入库；PDF/Word 需要引入专门的解析管道（排版提取、编码处理、可能的 OCR），复杂度高，规约将其列为**后置项**。先用白名单把入口收窄，保证"入知识库的内容一定是可解析的纯文本"。

局限说明：目前类型判断依据是**扩展名**而非文件内容嗅探（MIME sniffing），把 `.exe` 改名成 `.md` 可以绕过白名单——但随后会在第 ⑤ 步解析阶段被拦下（非 UTF-8 内容解析失败 → 400 且无脏数据），所以依然不会污染知识库。

**如需扩展支持 PDF/Word**，改动点是：白名单加入扩展名 + 在解析层接入对应解析器（如 pypdf / python-docx）。规约中的"上传失败无脏数据"等 Scenario 无需修改，天然兼容。
